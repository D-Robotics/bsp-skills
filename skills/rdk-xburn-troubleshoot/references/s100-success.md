# S100 / XBurn 1.2.1：一次完整烧录如何判读

**范围：** 用户提供的真实 S100 单板运行；Windows 主机，USB DFU+Fastboot，全量写入，目标 eMMC。以下只保留能区分阶段的证据。没有 S600 或 X5 的实测结果。

| 观察 | 能支持的结论 |
| --- | --- |
| 本次 DFU 的 13 项下载依次结束。HSM 退出项附近出现 PIPE，后续设备仍重新枚举，Acore 引导项继续完成 | 本次 PIPE 未阻断流程。若新日志在同处终止，需核对后续枚举及最终状态 |
| MCU 有 `McuOs Boot success!`、主域启动标志；Acore 摘要到 OP-TEE 切回 normal world；主机随后成功访问 Fastboot | 板端已经推进到能处理 Fastboot 请求；这些早期串口标志本身不证明 Ubuntu 启动 |
| Fastboot 写 NOR 启动区时进度停在约 26%，写入约 193 秒后返回成功；随后 eMMC 系统镜像的 77 个 sparse 分片完成 | 区分传输停滞与耗时的写入操作。不要用这个百分比或耗时给其他板设置超时 |
| 七个阶段完成，工具报告 SUCCESS；自动重启和启动检查均关闭 | 工具报告写入成功，没有本次工具独立读回或启动验证的证据 |
| 用户确认退出下载模式、重新上电后启动正常 | 该次运行的启动结果有用户确认；没有重启后的完整系统日志或版本记录 |

复用时只对照与当前日志相同的链路、项和结果。对多个尝试或多块板分别判断；不要用本例代替另一块板的证据。
